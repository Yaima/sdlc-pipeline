# Handoff: {slug}

Preconditions: `docs/features/{slug}/prd.md` exists and `state.json.stage` is `prd`. Otherwise stop and say what is missing. Run the gate check in `docs/pipeline/rules/roles.md` for the `handoff` gate.

1. Run role `requirements-analyst` with slug `{slug}` and the round number (starting at 1). Wait. Read `max_analyst_rounds` from `docs/pipeline/pipeline.json` (default 2).
2. If it reports conflicts or questions, show them to the user. List `[ADDS SCOPE]` items in their own block, each needing its own answer; "accept all defaults" applies only to the other items. If the round number equals `max_analyst_rounds` and it is still not CLEAR, show its BLOCKED list and stop; the human decides and re-runs. Wait for answers. Record each answer verbatim per `roles.md` "Recording gate answers". If an answer would remove or downgrade a `must` R-id, follow `roles.md` "Scope changes stop the pipeline" before editing. Apply PRD edits (keep R-ids stable; add new ones at the end; a removed R-id keeps its row, marked removed, with the gate reference). Re-run the analyst only if the PRD changed in substance.
3. When the analyst says `REQUIREMENTS: CLEAR`, run role `architect` with slug `{slug}`. Instruct it: the first task in `tasks.md` is a tracer bullet, the thinnest end-to-end path through every layer the feature touches, with a test that proves the path connects; later tasks widen it.
4. As soon as the architect has written `spec.md` (and `data-model.md`), set `state.json.spec_sha` = `git hash-object docs/features/{slug}/spec.md` and `data_model_sha` likewise, and set `stage: "handoff"`. Do this before asking anything, so a session that stops at the next step leaves a pinned spec. Then show the user the task list and risks. Ask them to confirm or reorder. Apply edits; if `spec.md` changed, re-pin.
5. Record the confirmation verbatim in `decisions.md`. Update `state.json`: `blast_radius` from the analyst's line, re-check `spec_sha` against `git hash-object`, append history. Commit the docs only if `commit_mode` is `agent`. Create the branch in `state.json.feature_branch` (default `feat/{slug}`) from `base_branch` if it does not exist. Any later edit to `spec.md` goes through this skill again so the SHA is refreshed.
6. Reply: task count, risk list, and say `/implement {slug}` is next.
